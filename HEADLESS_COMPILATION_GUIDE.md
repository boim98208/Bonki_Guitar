## 2. Compiling the VST3 Binary (Direct Toolchain)

When C++ source code is modified (e.g., DSP code in `DspNetworks/ThirdParty/` or `AdditionalSourceCode/`) and the HISE node structure has not changed:

### Step 1: Resave Projucer (Optional but Recommended)
Ensures project configuration and source files are synced to the Visual Studio solution:
```bat
"C:\Users\Ibrahim Rasyid\Documents\HISE\JUCE\Projucer\Projucer.exe" --resave "C:\Users\Ibrahim Rasyid\Documents\HISE Projects\Bonki_Guitar\Binaries\AutogeneratedProject.jucer"
```

### Step 2: Run MSBuild with 64-bit Native Host Toolchain
> [!CRITICAL]
> You **MUST** pass `/p:PreferredToolArchitecture=x64`.
> Default MSBuild invokes the 32-bit compiler host (`HostX86\x64\cl.exe`), which will run out of heap space (`fatal error C1002: compiler is out of heap space in pass 2`) during Whole Program Optimization (LTO/LTCG).

```bat
"C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MsBuild.exe" "C:\Users\Ibrahim Rasyid\Documents\HISE Projects\Bonki_Guitar\Binaries\Builds\VisualStudio2026\BonkiGuitar.sln" /p:Configuration=Release /p:Platform=x64 /p:PreferredToolArchitecture=x64 /m /verbosity:minimal
```

- Target: Builds both `BonkiGuitar_SharedCode.vcxproj` (produces `BonkiGuitar.lib`) and `BonkiGuitar_VST3.vcxproj` (produces `BonkiGuitar.vst3`).
- Output: `Binaries\Compiled\VST3\BonkiGuitar.vst3`

## 3. Compiling Only the DSP Dynamic Library (Development / Fast Iteration)

When iterating on custom DSP nodes (`amp.h`, `NAM_impl.h`, Faust/C++ nodes) without recompiling the entire plugin shell:

### Step 1: Compile the DSP Network Solution
```bat
"C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MsBuild.exe" "C:\Users\Ibrahim Rasyid\Documents\HISE Projects\Bonki_Guitar\DspNetworks\Binaries\Builds\VisualStudio2026\BonkiGuitar_DynamicLibrary.sln" /p:Configuration=Release /p:Platform=x64 /p:PreferredToolArchitecture=x64 /m /verbosity:minimal
```

### Step 2: Synchronize the DLLs
The dynamic library output resides in `DspNetworks\Binaries\dll\Dynamic Library\`. Ensure `BonkiGuitar.dll` and `BonkiGuitar2.dll` are in sync:
```powershell
Copy-Item "C:\Users\Ibrahim Rasyid\Documents\HISE Projects\Bonki_Guitar\DspNetworks\Binaries\dll\Dynamic Library\BonkiGuitar.dll" "C:\Users\Ibrahim Rasyid\Documents\HISE Projects\Bonki_Guitar\DspNetworks\Binaries\dll\Dynamic Library\BonkiGuitar2.dll" -Force
```

## 4. Full Headless Re-Export via HISE CLI

If changes are made to the HISE node graph, UI layouts, or script processors that require a full project C++ re-export from a preset (`.hip` or `.xml`):

> [!WARNING]
> Ensure the HISE GUI is completely closed prior to running CLI export commands to avoid file access collisions.

```bat
"C:\Users\Ibrahim Rasyid\Documents\HISE\projects\standalone\Builds\VisualStudio2026\x64\Release\App\HISE.exe" export "C:\Users\Ibrahim Rasyid\Documents\HISE Projects\Bonki_Guitar\Presets\BonkiGuitar_testingHammerons.hip" -p:VST3 -t:instrument -nolto
```

### Key CLI Flags:
- `export`: Compiles the project using default configuration.
- `export_ci`: Automated CI build variant (locks to VS 2026, relative paths, avoids copying into system plugin directories).
- `-p:VST3`: Sets plugin format to VST3 (`-p:ALL` for Standalone + VST3).
- `-t:instrument`: Project type (`instrument`, `effect`, `standalone`, or `midi`).
- `-nolto`: Deactivates link-time optimization (dramatically reduces build times during testing).
- `compile_networks -c:Release`: Headless command to compile only DSP networks in the active project directory.
